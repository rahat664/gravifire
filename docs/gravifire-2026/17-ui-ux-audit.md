# GRAVIFIRE visual UI/UX audit

**Date:** 2026-11-13
**Scope:** Read-only visual review of the existing product. No application code, scientific data, verdict logic, ranking weights, dependencies, or service configuration changed.
**Overall visual assessment:** Strong identity and credible research tone; the platform is visually cohesive at a glance, but mobile navigation and dense scientific screens limit quick orientation and comfortable scanning. The game is intentionally distinct from research surfaces. Recommendations below are for a later approved visual-only implementation.

## Capture method and coverage

Screenshots were captured through the existing Playwright installation using Chrome against the existing service at `http://localhost:3000` (PID 21384). Research routes were captured at exact **1920×1080** and **390×844** viewport sizes; separate full-page screenshots are retained for page-length review. Game routes were captured at both viewport sizes after a 5.5-second render wait. The capture notes report HTTP 200 for every route and no captured page errors or console errors. This was not a functional test suite or an axe run. Automated checks from Step 15.1 are inherited, not repeated here.

The dashboard interaction state uses Lunar habitat, Fire Prevention, BASS-II / PSI-25 record B1, and a hypothetical oxygen value of 22.2%. Other saved states include the expanded B1 provenance, the condition comparison, EMBER’s B1 evidence-gap response, and the M0 pause dialog. These states are for visual inspection; capture did not change source evidence or campaign data.

## Recommended cohesive design system

- **Typography:** one high-legibility sans family for interface/body text; a consistent 12/14/16/20/28/36 px scale; short, restrained uppercase eyebrow labels; monospace only for PSI IDs, record IDs and source hashes. Avoid using letter spacing on long values or explanatory sentences.
- **Color:** retain the dark research-console base and cyan primary accent; reserve amber for limitations/uncertainty, green for verified states and rose for mismatch/error states. Define named tokens for page, surface, raised surface, border, primary text, secondary text and state colors. Check actual contrast ratios during implementation rather than relying on appearance.
- **Spacing:** use a 4 px base scale (4, 8, 12, 16, 24, 32, 48 px); standardize section gaps, card padding and inter-action spacing. Reduce nested bordered boxes where a heading and whitespace suffice.
- **Cards:** one surface/border/radius system with consistent heading, metadata, body and action positions. Use selected state as a modest border/background change; avoid glow as the primary signal.
- **Buttons and links:** one filled primary action per panel, outlined secondary actions, text links for sources; keep 44 px minimum interactive height where practical and consistent visible focus. Separate source-navigation and external-citation links with labels and spacing.
- **Navigation:** consistent desktop global nav, an explicit mobile menu button, active-route state and contextual breadcrumbs/back links. Keep Mission Control/game access visible but visually secondary on scientific screens.
- **Scientific evidence:** preserve a fixed visual order for source identity, record kind/status, measured/source-reported values with units, hypothetical scenario values, interpretation status, limitation and source citation. Keep unknown and not-reported text explicit. Put raw source rows behind a disclosure, not in place of summarized readable fields.
- **Game HUD:** use a dedicated, restrained HUD token subset with solid/translucent backing, clear mission title, readable controls and separate review/evidence links. Keep all HUD elements within safe areas and do not alter the game camera or render engine.

## Safe implementation sequence after approval

1. Confirm the proposed tokens and type scale; capture a short before/after set on home, dashboard and ranking.
2. Improve the mobile navigation affordance and verify all primary routes remain keyboard reachable at 390 px and desktop.
3. Normalize type, spacing and action gaps; recheck evidence/status contrast without changing labels or state semantics.
4. Reduce ranking and Explorer visual density with progressive disclosure while keeping score, factors, provenance, record kinds and limitations available.
5. Refine comparison rows and dashboard evidence actions, preserving all measured values, units, citations and unknown states.
6. Reframe the Virtual Lab preview and refine game HUD scale/safe areas as separate visual-only changes; do not change physics, camera behavior, or game controls.
7. Repeat screenshots at both sizes, inspect focus and mobile layouts, run targeted regression/accessibility checks, and compare scientific text/contracts against the current baseline.

**Audit outcome:** No code was changed. Stop here for review and approval before visual implementation.
