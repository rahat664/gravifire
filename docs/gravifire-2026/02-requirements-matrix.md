### Source distinction

The official indexed summary confirms the central deliverable: an interactive dashboard that summarizes, ranks, and interprets findings to provide fire-safety insights. The detailed written requirements below are based on the accessible statement reproduction and are labelled as such. The video provides no verifiable content in this audit. In particular, “SI-powered” is the challenge’s wording, but the statement reviewed does not define SI as a general superintelligence model, require a specific foundation model, or prescribe an AI vendor. No such requirement is inferred here.

## 2. Priority definitions

- **P0 — Core challenge fit / demo blocker:** Explicitly required by the challenge’s central deliverable or a minimum evidence-integrity condition needed to make that deliverable scientifically usable.
- **P1 — Stated domain coverage / strong objective:** Explicitly described in the written Background or among the “may consider” objectives. Important for a convincing domain-complete solution; some objective bullets are optional by the challenge’s own wording.
- **P2 — Extension / broader coverage:** Useful stretch coverage, future datasets, or optional applications that are not needed to demonstrate the central deliverable.

The priority is a project implementation priority, not a NASA safety classification. “Implemented” means code inspected in this repository, not independent scientific validation of its claims.

## 4. Verifiable acceptance criteria for every P0

| P0 | Acceptance criteria |
|---|---|
| R-01 Interactive dashboard path | A user can reach investigation search/filter, an investigation summary, a relevance result, and its evidence-backed interpretation through visible interactive controls without needing a direct URL. Keyboard-operable controls and empty/no-match states are present. |
| R-02 Investigation summaries | For every investigation eligible for ranking, its detail/summary shows: objective or source-described purpose; fuel/material and sample/burner details when reported; environment/gravity; oxygen/pressure/airflow when reported; sensors/measurements when reported; record count/data type; and explicit “not reported/not ingested” states for unavailable fields. Each scientific claim/value links to a source record, document, or PSI source. |
| R-03 Relevance ranking | Given a named mission profile and target need (prevention, detection, or suppression), the system returns a stable ordered list of eligible investigations. Each rank item exposes the rule/criteria and weights or deterministic scoring basis, matched fields, missing/mismatched mission conditions, source coverage, and evidence links. Repeating the same profile/data produces the same order. UI/API labels it “relevance” or “research priority,” never material risk, probability of fire, safety grade, or certification. |
| R-04 Scientific interpretation | For each displayed fire-safety insight, the user can inspect the NASA source records and conditions supporting it, what was observed versus inferred, applicability (direct/analogical/out-of-domain), and at least one relevant limitation or unknown. A comparison alone cannot be described as causal; unsupported mission conditions produce an explicit abstention/coverage gap rather than a predicted outcome. |
| R-05 Traceability / uncertainty gate | Automated tests fail if a ranked investigation or displayed insight lacks source IDs/URLs, an evidence status, or its mission/data scope. A result with no applicable source record is visibly “insufficient evidence” and cannot produce a confident safety insight. The UI distinguishes NASA-reported facts from derived ranking/interpretation. |

P0 acceptance criteria intentionally do not require a general superintelligence or a predictive combustion model. The challenge text reviewed does not define a model class; deterministic, explainable retrieval/ranking can be assessed against the required user-visible behavior, while the app must accurately disclose its method.

## 5. Unresolved verification issues

1. **Official Resources tab:** Direct official challenge URL returned 502, so current linked source files/datasets and any additional requirements on that tab remain unverified. The secondary page states resources would be available on Nov 13 but exposed no resource list in the content inspected.
2. **Official full statement:** Its detailed sections were read from a local-event reproduction, not directly from the official page. Verify its current text against the official site before treating secondary-only details (including stated lunar environment numbers and partial-gravity data status) as authoritative.
3. **Video transcript:** English auto-generated caption metadata exists, but every timed-text retrieval attempted returned an empty body. No video-specific statement is confirmed. Retry via the YouTube transcript panel or obtain a supplied transcript/caption file.
4. **“SI-powered” meaning:** The written statement does not define SI or specify model/provider. Team should document its chosen method and avoid claiming general superintelligence. Whether judges expect a model-based feature is unresolved, not a verified requirement for an AGI system.
5. **Live NASA coverage:** The challenge’s examples include programs not present in GRAVIFIRE’s runtime registry. Confirm current PSI availability and all source/resource links before expanding coverage; do not treat repository absence as absence from NASA’s full archive.
